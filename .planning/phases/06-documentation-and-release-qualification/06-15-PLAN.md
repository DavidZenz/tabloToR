<objective>
Diagnose the current `PROVENANCE_KEY_MISMATCH` against a clean tracked snapshot and repair canonical provenance state only when the exact proposed changes have adequate evidence and explicit human approval.

Purpose: The top current Phase 06 verification records a live provenance failure, while the earlier 06-04 transition already reviewed a different 291-to-324 inventory change. This plan creates a distinct, checksum-bound reconciliation and does not revise or overwrite the 06-04 proposal.
Output: A reproducible mismatch report and exact delta; if every proposed identity and hash change is supportable and approved, an exact canonical update and passing local blocked-state assertion. If evidence or approval is incomplete, leave canonical records unchanged and record the unresolved blocker.

Atomicity rationale: keep this ten-file reconciliation together because its five checksum-bound proposal/review artifacts, four canonical provenance records, and final result summary must all describe the same approved input commit and delta. Splitting proposal review from application would separate the reviewer binding from the precise canonical changes it authorizes; the scope is one bounded reconciliation with fail-closed branches.
</objective>
