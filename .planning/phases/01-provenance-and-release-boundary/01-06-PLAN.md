<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Independent evidence files → integrated gate | Cross-document drift could create a false release result. |
| Human-approved identity → DESCRIPTION | Transcription or inference could expose wrong contact/URLs. |
| Gate status → later publication workflow | A generic command failure could be mislabeled as safe blockage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-021 | Tampering | cross-document parsers | critical | mitigate | Exact schemas/cardinality/cross-links and per-parser reason codes. |
| T-01-022 | Elevation of privilege | release-ready calculation | critical | mitigate | Fail closed; synthetic-only success; real assertion accepts only exact intentional blocker set. |
| T-01-023 | Spoofing | identity/package parity | high | mitigate | Approved contact/slug/URL/issue/security values cross-checked exactly. |
| T-01-024 | Repudiation | reviewer/signature evidence | medium | mitigate | Require reviewer/date on rights, provenance, name, governance, and repository records. |
| T-01-025 | Information disclosure | integrated diagnostics | high | mitigate | Emit field/reason identifiers without sensitive values or raw evidence contents. |
| T-01-026 | Denial of service | online/stale evidence | medium | mitigate | Deterministic offline fixtures and explicit freshness/source failures; no silent online skip. |
</threat_model>
