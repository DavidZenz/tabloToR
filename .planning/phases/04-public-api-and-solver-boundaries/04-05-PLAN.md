<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Solver failures to caller code | Callers consume condition classes and diagnostic fields to choose recovery behavior. |
| Candidate/native evidence to diagnostic storage | Untrusted or stale evidence must not be represented as accepted numerical state. |
| Native resources to cleanup outcome | Native factors and workspaces must be released even when errors are raised. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | Conditions and diagnostic status fields | high | mitigate | Derive accepted/retryable state from central transaction records, persist a fresh running/final envelope at every public solve boundary, and attach stable typed classes rather than message-derived classifications. |
| T-04-03 | Denial of Service / Tampering | Native cleanup and capability evidence | high | mitigate | Preserve unconditional cleanup, expose cleanup/capability outcomes, and test both successful and exceptional exits. |
</threat_model>
